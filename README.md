# HealthConnector

Личная система сбора данных о здоровье: Android-приложение читает **Health Connect** (браслет Fitbit, Mi Fitness, Google Fit, датчики телефона, умные весы Xiaomi), принимает пищевой дневник **FatSecret**, воду и самочувствие, а **Google Apps Script** складывает всё в таблицу **Google Sheets «Dashboard»** и в архив на **Google Drive**.

| | |
| --- | --- |
| Текущая версия | **1.8.1** (`versionCode 56`) |
| Application ID | `ru.doronin.healthconnector.stable` (TEST-сборка: `…stable.test`) |
| Android | minSdk 26, targetSdk 35, compileSdk 36; Kotlin, Gradle KTS |
| Сервер | `apps-script/Code.gs` — один файл Apps Script, публикуется автоматически из `main` |
| Хранилище | Google Sheets (дневные итоги, дневники) + Google Drive (подробные данные, JSON.gz) |

История изменений — [CHANGELOG.md](CHANGELOG.md).

## Что умеет

**Данные браслета и телефона (Health Connect → `HC_Дни`)**
- шаги, дистанция, активные и общие калории, этажи и набор высоты;
- сон: длительность, стадии (глубокий, лёгкий, REM, бодрствование), основной сон и дневной;
- пульс (средний, мин., макс.), пульс покоя, HRV (RMSSD), SpO₂, частота дыхания, температура кожи, VO₂ max;
- тренировки с пульсом, скоростью, каденсом, мощностью; вес.

**Целостность** — шаги не считаются дважды, когда их пишут несколько приложений; каждый день проверяется на полноту и при необходимости перечитывается (см. [Целостность данных](#целостность-данных)).

**Питание** — отчёт FatSecret передаётся через «Поделиться» → *FatSecret → Health Connector*; сервер сверяет КБЖУ приёмов пищи с суточным итогом и только тогда пишет `Трекер_питания` / `Питание`. Подробно: [docs/FATSECRET_IMPORT.md](docs/FATSECRET_IMPORT.md).

**Вода** — виджет на рабочий стол (+250 / +500 мл, отмена), работает без сети; запись в Health Connect по отдельному разрешению; итог дня — в «Дневник» → «Вода, л».

**Самочувствие** — уведомление утром (09:30) и вечером (21:30) с ответом в одно нажатие; полная форма: энергия, настроение, мышцы, стресс (1–5) и метки дня (кофе поздно, алкоголь, болею, плохо спал, тяжёлый ужин, крепатура); итог — в «Дневник» → «Самочувствие 1-5».

**Весы Xiaomi Mi Body Composition Scale 2** (XMTZC05HM) — приём по BLE в фоне, расчёт состава тела, лист `HC_Состав_тела`.

**Этажи по датчикам телефона** — барометр + шагомер, запись в Health Connect. Подробно: [docs/PHONE_FLOOR_TRACKING.md](docs/PHONE_FLOOR_TRACKING.md).

**Облачные источники** — Fitbit Web API и Google Health API на сервере как запасной путь для сна и показателей, которые не попадают в Health Connect. Подробно: [docs/fitbit-stable-sync.md](docs/fitbit-stable-sync.md).

**Управление** — «Остановить всё», «Что на сервере» (кто держит сервер, фоновые задачи, ход архивации), пауза фоновых задач сервера, выбор источника шагов, сторож синхронизации с уведомлениями.

## Как устроено

```text
 Fitbit · Mi Fitness · Google Fit · телефон · весы
                    │
             Health Connect
                    │  чтение по дням, сверка источников
                    ▼
   ┌──────────── Android: HealthConnector ─────────────┐
   │ HealthSyncStreamer   — синхронизация дней          │
   │ LocalStore + Outbox  — вода, самочувствие (офлайн) │
   │ ShareCsvActivity     — FatSecret                   │
   │ MiScale*             — весы по BLE                 │
   │ SyncControl          — остановка, статус сервера   │
   └───────────────────────┬───────────────────────────┘
                           │ HTTPS POST (API-токен)
                           ▼
   ┌──────────── Google Apps Script (Code.gs) ─────────┐
   │ doPost: проверка токена → действия без замка       │
   │         (статус, остановка) → script lock → запись │
   │ фоновые задачи: автоархивация, Fitbit, обслуживание│
   └──────────────┬───────────────────────┬────────────┘
                  ▼                       ▼
     Google Sheets «Dashboard»    Google Drive
     HC_Дни, Дневник, Питание…    «HealthConnector — подробные данные v4»
     (итоги и отчёты)             (сырые измерения, сессии, удаления: JSON.gz)
```

Принципы:
- **Дневной итог считается на телефоне** из всех исходных отсчётов и не зависит от того, сохранились ли подробные данные.
- **Подробные данные — только на Drive.** Таблица хранит итоги и то, что нужно отчётам; у Google Sheets жёсткий лимит 10 млн ячеек на книгу.
- **Ничего не удаляется без проверки.** Файл архива читается обратно и сверяется по SHA-256 до удаления строк из таблицы.
- **Сбой одной части не роняет остальное.** Нет Drive — сводка дня всё равно пишется; не ушли удаления — дни всё равно синхронизируются; сломался один день — остальные идут дальше.

## Синхронизация Health Connect

Ручная синхронизация запускается из открытого приложения (так Health Connect отдаёт данные всех приложений), фоновая — WorkManager каждые 6 часов.

1. **Проверка сервера.** `GET` веб-приложения: версия схемы и время сервера (для остановки по времени, см. ниже).
2. **План.** `healthSyncPlanV3` возвращает `repairDates` — дни, которые надо перечитать (нет строки, день не завершён, нет ожидаемого показателя), и `storesHighVolumeRaw`.
3. **Выбор дней** (`SyncDatePlanner`): вчера и сегодня + дни из плана; фон — не больше 3 самых старых проблемных дней за запуск. Окно — последние 30 дней (столько хранит Health Connect).
4. **Изменения Health Connect.** Changes API: изменённые дни добавляются к списку; удалённые записи уходят `healthChangesV3`. Если удаления не дошли — дни всё равно синхронизируются, а удаления повторятся.
5. **Дни.** Ручная — по 2 дня одновременно (чтение Health Connect параллельно, запросы к серверу строго по одному), фоновая — по одному. Для каждого дня:
   - сводные значения Health Connect (Aggregate API) и сверка с каждым источником (`CumulativeResolver`);
   - ранняя сводка (шаги, сон) → `HC_Дни` с `SyncComplete=false`;
   - пульс, SpO₂, HRV, дыхание, температура, скорость, каденс, мощность, тренировки → статистика дня; подробные отсчёты пакетами по 2000 → Drive;
   - итоговая сводка `dayFinal=true` → `HC_Дни`, сервер пересчитывает `Quality`.
6. **Change tokens** сдвигаются только после полностью успешного запуска — иначе изменения перечитаются в следующий раз.

**Устойчивость:** до 6 попыток на запрос; «сервер занят», таймаут, обрыв связи (смена сети, звонок) — повторяются. Сетевой запрос обрывается сразу при остановке.

**Остановка** («Остановить всё»): отменяет ручную и фоновую синхронизацию и очередь на телефоне, закрывает текущее соединение и через `abortSyncV1` останавливает синхронизации других копий приложения (сервер отклоняет запросы запусков, начатых до остановки). Фоновая синхронизация продолжится по расписанию через 6 часов.

## Целостность данных

**Шаги без двойного счёта.** Шаги, дистанция и активные калории суммируются отдельно по каждому источнику (точные дубли записей убираются, записи через полночь делятся по времени). Если сводка Health Connect больше любого отдельного источника более чем на 15 % — это сложение дублей, берётся основной источник (Fitbit → Google Fit → Mi Fitness → прочие) или выбранный вручную (Синхронизация → «Выбрать источник»). Дополнительно проверяется длина шага 0,45–1,4 м.

**Полнота каждого дня.** Сервер определяет «ожидаемые» показатели — те, что есть хотя бы в 60 % дней за последние 30 (минимум 5 дней истории), — и проверяет каждый завершённый день. Неполным считается день без строки, с `SyncComplete=false`, без ожидаемого показателя или с менее чем 300 шагами. Такой день перечитывается до 3 раз; потом в `Quality` фиксируется «в источнике нет данных», чтобы не повторять бесконечно.

Колонки `HC_Дни` для контроля:

| Колонка | Что в ней |
| --- | --- |
| `StepsBySource` | шаги каждого источника, например «Fitbit 15 210; Mi Fitness 14 980» |
| `ActivitySource` | откуда взяты шаги: сводка Health Connect, источник или ручной выбор |
| `QualityFlags` | предупреждения: завышенная сводка, повторы записей, шаги не сходятся с дистанцией |
| `Quality` | `OK` или чего не хватает и сколько раз проверено |
| `QualityChecks` | число проверок (0–3) |
| `SyncComplete` / `CompletedAt` | день прочитан полностью и когда |

Сторож синхронизации (каждые 6 ч) присылает уведомление, если в `HC_Дни` нет вчерашнего дня, есть неполные дни за неделю, вода/самочувствие не отправляются больше 12 ч или сервер недоступен — не чаще раза в сутки на проблему.

## Где хранятся данные

### Google Sheets «Dashboard»

| Лист | Назначение | Пишет |
| --- | --- | --- |
| `HC_Дни` | одна строка на день: все итоги + контроль качества | синхронизация |
| `HC_Тренировки` | тренировки (сессии) | синхронизация |
| `HC_Сон` | сессии сна со стадиями (`StagesJson`) | синхронизация, Fitbit/Google Health |
| `HC_Состав_тела` | измерения весов Xiaomi | весы |
| `HC_Вода`, `HC_Самочувствие` | записи из приложения (upsert по id) | очередь отправки |
| `HC_Журнал` | журнал запросов и ошибок | сервер |
| `HC_Измерения` | прежнее место сырых измерений; **переносится на Drive автоархивацией** | — |
| `Трекер_питания`, `Питание` | FatSecret по приёмам пищи и продуктам | импорт FatSecret |
| `Дневник` | ручной дневник; сервер заполняет «Вода, л» и «Самочувствие 1-5», только если в ячейке нет формулы | сервер, вручную |
| `Дашборд`, `Аналитика`, `Индекс эффективности`, `Сон`, `Тренировки`, `Замеры`, `Анализы`, `Профиль`, `Архив` | отчёты и справочные листы на формулах | вручную |

### Google Drive

Папка **«HealthConnector — подробные данные v4»** (приватная). Файлы `<день>__<источник>__<sha256>.json.gz`, внутри: версия схемы, ID таблицы, часовой пояс, источник, день, операция, заголовки, строки. Файлы неизменяемые и именуются по содержимому: повторная запись того же пакета переиспользует файл. Это **история событий**, а не текущее состояние: для анализа нужно брать последнюю версию записи по `Id` + `SyncedAt` и применять события удаления (`HealthConnectChanges`).

Что туда попадает: подробные измерения, тренировки и сон (вместе со сводкой), события удаления Health Connect и прежние строки `HC_Измерения` (операция `sheet-archive`).

## Сервер (Apps Script)

`apps-script/Code.gs` — веб-приложение, выполняется от имени владельца. Каждый `POST` содержит `token` (сравнение в постоянном времени) и `action`.

| Действие | Что делает |
| --- | --- |
| `healthSyncPlanV3` | план: дни на восстановление, ожидаемые показатели, режим хранения |
| `healthSyncV3` | сводка дня, тренировки, сон; подробные измерения → Drive |
| `healthArchiveV4` | только подробные данные → Drive |
| `healthChangesV3` | удаления Health Connect: события → Drive, строки сна/тренировок удаляются |
| `fatsecretCsv` | импорт FatSecret с проверкой сумм |
| `hydrationV1`, `wellbeingV1` | вода и самочувствие |
| `bodyCompositionV1` | весы |
| `dashboardSnapshotV1` | данные для дашборда в приложении |
| `fitbitCloud*`, `fitbitRepairSleepV1`, `googleHealth*` | облачные источники: настройка OAuth, статус, восстановление сна |
| `serverStatusV1` | **без замка:** кто держит замок и сколько, фоновые задачи, ход автоархивации, последняя ошибка Drive |
| `abortSyncV1` | **без замка:** остановить запуски, начатые раньше; `pauseServerJobs` — пауза фоновых задач |

`GET` без токена возвращает версию схемы, готовность Drive и краткий ход автоархивации (без данных о здоровье).

**Замок.** Все записи идут под одним `LockService.getScriptLock()` (ожидание до 20 с). Сервер запоминает, кто взял замок; ответ «занят» говорит, кем и сколько секунд.

**Фоновые задачи сервера** (триггеры):

| Задача | Когда | Что делает |
| --- | --- | --- |
| `archiveRawMeasurementsV4` | каждые 5 мин, **запускается сама** при ≥ 50 тыс. строк в `HC_Измерения` или при ошибке лимита ячеек | переносит строки с конца листа блоками по 4000 на Drive: запись → чтение обратно → сверка → удаление; замок держится на один блок; по завершении удаляет себя и обновляет лист «Архив» |
| `fitbitScheduledSyncV1` | каждые 6 ч | досинхронизация Fitbit за 3 дня |
| `compactOldMeasurementsV1` | ежедневно в 4:00 | старое обслуживание `HC_Измерения` |
| `migrateMeasurementsTo5mV1`, `archiveDashboardHistoryV1` | при включении вручную | прежние миграции (не нужны после автоархивации) |

Пауза из приложения останавливает все эти задачи, кроме уже начатой перезаписи `HC_Измерения`, которая блокирует запись и поэтому доводится до конца.

Функции для ручного запуска из редактора Apps Script: `startRawArchiveV4()`, `installRawFilesV4()`, `configureFitbitOAuthV1(...)`, `measurementMaintenanceStatusV1()`.

## Приложение (Android)

Экраны: **Дашборд** (итоги дня, «Сегодня»: вода и самочувствие, этажи), **Синхронизация** (запуск, журнал, «Управление синхронизацией»), **Настройки** (адрес и токен, фон, цель по воде, напоминания, весы, этажи, Fitbit/Google Health). Плюс виджет «Вода» и форма самочувствия.

`app/src/main/java/ru/doronin/healthconnector/`:

| Область | Файлы |
| --- | --- |
| Синхронизация | `HealthSyncStreamer` (основной поток), `HealthAggregateReader`, `HealthChangesTracker`, `CumulativeResolver`, `SyncDatePlanner`, `HealthSourceCatalog`, `MeasurementBuckets`, `ServerCompatibility` |
| Запуск и контроль | `StreamingMainActivity`, `PermissionGateActivity`, `ManualSyncWorker`/`Scheduler`, `BackgroundSyncWorker`/`Scheduler`, `SyncRuntime` (журнал, `SyncRunGate`), `SyncForeground`, `SyncControl`, `SyncControlCard` |
| Локальные данные | `local/LocalStore` (SQLite: вода, самочувствие, очередь), `local/OutboxWorker`, `local/ServerApi` |
| Вода, самочувствие, сторож | `water/*`, `wellbeing/*`, `watchdog/*`, `FeatureCards` |
| FatSecret | `ShareCsvActivity`, `FatSecretCsvNormalizer` |
| Весы | `MiScale*` |
| Этажи | `floors/*`, `source/*` |
| Облако, дашборд, настройки | `FitbitCloudApi`, `GoogleHealthCloudApi`, `DashboardApi`, `ConfigAutoRestore`, `SecureTokenStore`, `EndpointSecurity` |

Разрешения Health Connect: чтение всех показателей обязательно (без полного набора синхронизация не стартует, чтобы не затереть данные), плюс чтение в фоне. Запись этажей и воды — необязательные отдельные разрешения.

Настройки (`settings` SharedPreferences): `endpoint`, `days`, `background_sync_enabled`, `water_goal_ml`, `wellbeing_reminders_enabled`, `wellbeing_morning_time` / `evening_time`, `activity_source_override`; токен — в `SecureTokenStore`.

## Безопасность

- Только HTTPS (`usesCleartextTraffic=false`, проверка адреса в `EndpointSecurity`).
- API-токен хранится в Android Keystore (AES-GCM) и не попадает в экспорт настроек; на сервере — в Script Properties.
- Действия статуса и остановки тоже требуют токена; `GET` отдаёт только версии и счётчики.
- Внешний текст (продукты FatSecret, заметки) экранируется от формульных инъекций перед записью в таблицу.
- Release-сборка: `debuggable=false`, R8.
- Архив на Drive приватный; ссылки на него не публиковать — это персональные медицинские данные.

## Сборка, выкладка, установка

**GitHub Actions**

| Workflow | Когда | Что делает |
| --- | --- | --- |
| `android.yml` | PR, push в `main`, вручную | `node --check` и node-тесты сервера, unit-тесты, TEST APK (артефакт `health-connector-test-apk`), release-сборка |
| `apps-script-deploy.yml` | push в `main` с изменениями `apps-script/**`, вручную | `clasp pull` → замена `Code` → `clasp push` → новая версия → обновление существующего развёртывания (URL не меняется) → проверка опубликованной версии и печать хода автоархивации |

Секреты: `APPS_SCRIPT_ID`, `APPS_SCRIPT_DEPLOYMENT_ID`, `CLASPRC_JSON`; для стабильной подписи — `HC_SIGNING_KEY_B64`, `HC_SIGNING_STORE_PASSWORD`, `HC_SIGNING_KEY_ALIAS`, `HC_SIGNING_KEY_PASSWORD`. Настройка развёртывания: [docs/APPS_SCRIPT_DEPLOY.md](docs/APPS_SCRIPT_DEPLOY.md).

**Порядок изменений:** ветка → PR → CI зелёный → merge в `main` → сервер публикуется сам → TEST APK из сборки `main`.

**Установка.** Сейчас ставится TEST APK (`HC <версия> TEST`, id `…stable.test`) рядом с основной копией. Стабильный APK публикуется только при настроенных секретах подписи; **не менять applicationId и сертификат**, иначе новая версия не встанет поверх старой. Если стоят обе копии — фоновую синхронизацию оставлять включённой только в одной.

Локально: `gradle :app:testReleaseUnitTest` и `node --test tests/*.test.cjs`.

## Тесты

- **Сервер** (`tests/*.test.cjs`, Node, сервисы Google подменены): архив на Drive и проверка чтением обратно, автоархивация `HC_Измерения` (полный перенос, сбой проверки не удаляет строки, повтор без дублей, блокировка по формулам, пауза), удаления без полного просмотра листа, совместимость V3, полнота дней и план восстановления, остановка и статус, вода и самочувствие, защита от переполнения.
- **Android** (`app/src/test`, JUnit): сверка источников шагов (включая реальный случай 21.10.2026), выбор дней, правила сторожа, расписание напоминаний, FatSecret CSV, весы, этажи, каталог источников, 5-минутные корзины.

## Эксплуатация и диагностика

Первое, что смотреть: **Синхронизация → «Что на сервере»** и журнал синхронизации на том же экране; на сервере — `HC_Журнал`.

| Симптом | Причина и что делать |
| --- | --- |
| Новые дни не появляются, существующие обновляются | таблица упёрлась в 10 млн ячеек; автоархивация запускается сама — проверить ход в «Что на сервере» |
| «Сервер занят: …, N с» | замок держит указанный запрос или задача; подождать или «Остановить всё» / пауза задач сервера |
| Шаги примерно вдвое больше | смотреть `StepsBySource` / `ActivitySource`; при необходимости выбрать источник вручную |
| Уведомление «Неполные дни» | приложение дочитает их само; если показателя нет и в приложении браслета — браслет его не записал |
| Файлы не появляются на Drive | «Что на сервере» → последняя запись в Drive; при `Raw file storage ready: false` в логе развёртывания — запустить `installRawFilesV4()` в редакторе и переразрешить доступ |
| FatSecret не виден в «Поделиться» / импорт отклонён | [docs/FATSECRET_IMPORT.md](docs/FATSECRET_IMPORT.md#6-диагностика); не ослаблять проверку сумм |
| APK не ставится поверх | другой applicationId или подпись |
