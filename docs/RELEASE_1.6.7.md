# Health Connector 1.6.7 — исправление синхронизации и диагностика

Дата: 7 сентября 2026 года

## Причина ошибки

Сообщение «Тайм-аут блокировки: другой процесс слишком долго удерживает блокировку» возникало при пересечении нескольких запросов синхронизации.

Одновременно могли выполняться:

- ручная синхронизация из приложения;
- фоновая синхронизация WorkManager;
- длительный запрос к Google Apps Script, удерживающий `ScriptLock`.

На стороне Apps Script блокировка ожидалась до 30 секунд. При превышении этого времени сервер возвращал ошибку, а Android-приложение не распознавало конфликт как временный и не повторяло запрос.

## Изменения в версии 1.6.7

### Защита от параллельных запусков

Добавлен единый локальный координатор `SyncRunGate`.

- Ручной и фоновый процессы больше не выполняются одновременно.
- Ручной запуск ожидает завершения уже работающей синхронизации.
- Фоновый запуск при занятом координаторе корректно пропускается и завершается без ложной ошибки.
- После завершения, отмены или исключения локальная блокировка гарантированно освобождается.

### Автоматическое восстановление после временных ошибок

Запросы к Google Apps Script теперь повторяются до четырёх раз с увеличивающейся паузой.

Повтор выполняется при:

- `LOCK_BUSY`;
- сообщениях о занятой блокировке старого Apps Script;
- сетевом тайм-ауте;
- HTTP 429;
- HTTP 5xx.

Операции синхронизации остаются идемпотентными: повторная отправка обновляет те же записи и не должна создавать дубликаты.

### Изменения Apps Script

В `apps-script/Code.gs` длительное ожидание

```javascript
lock.waitLock(30000);
```

заменено на короткую проверку `tryLock(5000)`.

Если сервер занят, возвращается структурированный ответ:

```json
{
  "ok": false,
  "errorCode": "LOCK_BUSY",
  "message": "Сервер занят другой синхронизацией. Приложение повторит запрос автоматически."
}
```

Чтобы это изменение заработало на сервере, необходимо создать новую версию развертывания веб-приложения Apps Script.

### Раскрывающаяся диагностика

На странице «Синхронизация» добавлен блок «Диагностика синхронизации» с тремя раскрывающимися разделами:

1. **Ручная синхронизация**
2. **Фоновая синхронизация**
3. **Google Sheets и сеть**

В журнале отображаются:

- дата и время события;
- этап выполнения;
- начало и завершение запуска;
- чтение Health Connect;
- проверка версии Apps Script;
- отправка данных;
- номер повторной попытки;
- конфликт серверной блокировки;
- сетевой тайм-аут;
- ошибка разрешений Health Connect;
- класс и текст исключения.

API-токен, содержимое медицинских данных и полный URL в диагностический журнал не записываются.

Хранится не более 120 последних событий.

### Перенос исправления 1.6.6 в основной код

Ограничение фоновой синхронизации теперь находится непосредственно в основной ветке, а не применяется только во время специальной сборки.

- Фоновый запуск обрабатывает последние два дня.
- Единичное удаление записи больше не расширяет фоновую задачу до безусловной пересинхронизации 30 дней.
- Ручная синхронизация по-прежнему может обработать выбранный пользователем диапазон и исторические изменения.

## Версия и совместимость

- Version name: `1.6.7`
- Version code: `21`
- Application ID: `ru.doronin.healthconnector.stable`
- Минимальная версия Android: 8.0
- APK подписан прежним совместимым ключом и устанавливается поверх версии 1.6.6.
- Настройки, endpoint и защищённый API-токен при обновлении сохраняются.

## Установка

1. Скачать `HealthConnector-1.6.7-diagnostics.apk`.
2. Установить APK поверх текущей версии приложения.
3. Не удалять старую версию и не очищать её данные.
4. Открыть приложение и выполнить ручную синхронизацию.
5. При ошибке раскрыть соответствующий раздел диагностики.

## Обновление Apps Script

1. Открыть Google Таблицу, связанную с Health Connector.
2. Перейти в **Расширения → Apps Script**.
3. Заменить содержимое `Code.gs` файлом `apps-script/Code.gs` из репозитория.
4. Выбрать **Развернуть → Управление развертываниями**.
5. Открыть текущее веб-приложение для редактирования.
6. Выбрать **Новая версия** и подтвердить развёртывание.
7. URL `/exec` и API-токен менять не требуется.

## Проверка

Успешный сценарий:

- ручной запуск начинается без конфликта с WorkManager;
- в статусе последовательно отображаются чтение и отправка;
- в разделе «Google Sheets и сеть» видны успешные ответы;
- синхронизация завершается количеством дней, тренировок, измерений и источников;
- фоновая синхронизация не создаёт параллельный запрос.

Если сервер уже занят, в журнале должна появиться повторная попытка, после которой синхронизация продолжится автоматически.
