# HealthConnector v4: отдельные файлы без активации старого архива

Эта реализация заменяет условие `ARCHIVE_DISABLED` для `healthArchiveV4`.

- Google Sheets `HC_Дни`: только компактная ежедневная сводка.
- Новый `healthArchiveV4`: подробные записи (пульс, тренировки, сон, исходные отсчёты) прямо в сжатые JSON-файлы папки **HealthConnector — подробные данные v4** на Google Drive.
- Папка создаётся **автоматически при первой непустой подробной выгрузке**, её ID сохраняется в Script Properties как `RAW_FILES_V4_FOLDER_ID`.
- Не требуется запуск `installDriveArchiveV1`, `archiveDashboardHistoryV1` или каких-либо миграционных триггеров.
- Существующие листы, архив V1 и его свойства остаются без изменений; автоматическое удаление/перенос старых записей отсутствует.
- Каждый файл проходит обратное чтение и проверку SHA-256 перед подтверждением; повторный запрос с тем же содержимым не создаёт дубликат файла.
- Файлы делятся на проверяемые части не более 2000 строк и группируются по дате, что предотвращает переполнение памяти/лимиты Apps Script. Это не один непрерывно редактируемый файл. Для ML сохранена возможность объединить все части.
- Оригинальные записи не складываются в новые листы Sheets. Если Google Drive недоступен, сервер возвращает ошибку и клиент оставляет `SyncComplete=false`.

## Проверка

После публикации открыть **тот же URL Web App** в браузере. Для версии 4 поле `rawStorage` показывает статус:
- `{"ready":true,"mode":"on-demand-files"}` — Web App может обратиться к Google Drive, при первой синхронизации создаст папку;
- `{"ready":false,...}` — Google Drive не авторизован для аккаунта, от которого развернут Apps Script. Владелец должен открыть проект Apps Script, запустить функцию `rawFilesReadyV4_` через обёртку или специально предусмотренный ручной тест, разрешить нужные scopes, а затем переопубликовать deployment при необходимости.

Для ручной проверки из редактора Apps Script удобно выполнить функцию `installRawFilesV4` (если Google просит разрешения, их может предоставить только владелец):
```js
function installRawFilesV4() {
  const folder = rawFilesFolderV4_();
  return { ok: true, folderUrl: folder.getUrl() };
}
```
Эта функция создаёт только приватную папку, не мигрирует и не удаляет данные.

**Security:** файлы содержат персональные медицинские измерения. Не делайте папку публичной и не выкладывайте ZIP/JSON в GitHub. Для построения модельного датасета потребуются дедупликация событий, контроль часовых поясов и применение `HealthConnectChanges`.
