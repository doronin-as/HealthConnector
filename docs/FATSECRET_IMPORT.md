# FatSecret import — архитектура, ограничения и runbook

> Актуально для **HealthConnector 1.6.5** (`versionCode 19`), 02.09.2026.
>
> Этот документ нужен как рабочая память проекта: что уже реализовано, почему реализация устроена именно так, где диагностировать ошибки и что делать при следующих изменениях FatSecret.

## 1. Что именно реализовано

HealthConnector **не является нативно подключаемым приложением внутри списка интеграций FatSecret**. Интеграция реализована через системный Android Share Sheet:

```text
FatSecret
  → экспорт / отправка пищевого отчёта
  → Android «Поделиться»
  → «FatSecret → Health Connector 2»
  → ShareCsvActivity
  → нормализация CSV
  → HTTPS POST в Google Apps Script
  → проверка целостности
  → Google Sheets
```

Это отдельный поток от синхронизации Health Connect.

### Health Connect

Приложение читает данные Health Connect и отправляет их в Apps Script. В Android Manifest используются `READ_*` permissions; HealthConnector не является writer-приложением для FatSecret.

### FatSecret

FatSecret передаёт экспортированный пищевой отчёт в HealthConnector через Android. Приложение обрабатывает CSV, затем отправляет его на сервер с:

```json
{
  "action": "fatsecretCsv",
  "fileName": "...",
  "csvText": "...",
  "uploadedAt": "...",
  "sourceMimeType": "...",
  "normalizedMealLabels": 0
}
```

Токен добавляется приложением отдельно и хранится через `SecureTokenStore`.

## 2. Точки входа Android

Файл: `app/src/main/AndroidManifest.xml`

`ShareCsvActivity` зарегистрирована для:

- `ACTION_SEND` + `*/*`;
- `ACTION_SEND_MULTIPLE` + `*/*`;
- `ACTION_VIEW` для `content://` / `file://` и известных текстовых/CSV MIME-типов.

Wildcard `*/*` для Share используется намеренно. На разных версиях FatSecret / Android / MIUI отчёт может приходить как `text/*`, `application/csv`, `application/vnd.ms-excel`, `application/octet-stream` или другой MIME. Слишком узкий intent-filter приводил к тому, что HealthConnector вообще не появлялся в системном меню «Поделиться».

`ShareCsvActivity` умеет получать содержимое через:

- `Intent.EXTRA_STREAM`;
- `ACTION_SEND_MULTIPLE` (сейчас обрабатывается первый URI);
- `ClipData`;
- `Intent.data`;
- `EXTRA_TEXT`;
- `EXTRA_HTML_TEXT`.

Ограничение размера входного отчёта: **5 МБ**.

## 3. Почему понадобилась предобработка CSV на Android

Apps Script исторически знает ограниченный набор канонических приёмов пищи:

```text
Завтрак
Обед
Полдник
Ужин
Перекус/Другое
```

Но в FatSecret пользователь может включать дополнительные слоты:

```text
До Завтрака
После Завтрака
До Обеда
Полдник
До Ужина
После Ужина
```

Основные `Завтрак`, `Обед`, `Ужин`, `Перекус/Другое` при этом остаются отдельными слотами.

До версии 1.6.5 дополнительные слоты могли не попасть в сумму приёмов пищи, хотя входили в суточный итог FatSecret. В результате сервер правильно отклонял импорт по проверке целостности.

### Известный инцидент 01.09.2026

В `HC_Журнал` было зафиксировано:

```text
01.09.2026: ERROR —
kcal meals=2434, daily=2568;
fat meals=89.68, daily=92.38;
carbs meals=233.82, daily=248.65;
protein meals=176.04, daily=188.63
— import rejected
```

То есть из распознанных приёмов пищи выпадал блок на:

```text
134 kcal
2.70 g fat
14.83 g carbs
12.59 g protein
```

После проверки настроек FatSecret стало видно, что используются дополнительные слоты (в частности, включён `До Завтрака`). В 1.6.5 обработка сделана на уровне класса проблемы: поддерживаются все известные дополнительные слоты, а не только конкретное значение из этого случая.

## 4. Канонизация приёмов пищи в 1.6.5

Файл: `app/src/main/java/ru/doronin/healthconnector/ShareCsvActivity.kt`

### Остаются отдельными

| FatSecret | Внутреннее имя |
|---|---|
| Завтрак / Breakfast | `Завтрак` |
| Обед / Lunch | `Обед` |
| Полдник / Afternoon Snack | `Полдник` |
| Ужин / Dinner | `Ужин` |

### Объединяются в `Перекус/Другое`

| FatSecret |
|---|
| Перекус/Другое |
| Перекусы/Другое |
| Закуски/Другое |
| Снэки/Другое |
| Snacks/Other |
| Snack/Other |
| Snacks & Other |
| Snack & Other |
| До Завтрака / Before Breakfast |
| После Завтрака / After Breakfast |
| До Обеда / Before Lunch |
| До Ужина / Before Dinner |
| После Ужина / After Dinner |

### Важное поведение при объединении

Если в один день заполнены, например:

```text
До Завтрака
Перекус/Другое
После Ужина
```

приложение не создаёт три одинаковых заголовка и не позволяет одному блоку перезаписать другой.

Оно создаёт один канонический блок `Перекус/Другое` и:

1. суммирует КБЖУ заголовков;
2. добавляет строки продуктов из всех исходных блоков;
3. удаляет промежуточные строки `Итого` / `Daily Total`;
4. сериализует корректный CSV;
5. только после этого отправляет CSV в Apps Script.

Колонки питания в экспорте FatSecret, используемые текущей реализацией:

```text
index 1 → kcal
index 2 → fat
index 4 → carbs
index 7 → protein
```

Суммирование выполняется в `mergeMealHeaders()`.

CSV разбирается собственным `parseCsvRows()`, который учитывает:

- quoted fields;
- запятые внутри кавычек;
- `""` внутри quoted field;
- CRLF / LF;
- BOM.

После преобразования используется `serializeCsvRows()`.

## 5. Серверная часть (Google Apps Script)

Файл: `apps-script/Code.gs`

`doPost()` маршрутизирует `action === 'fatsecretCsv'` в `importFatSecretCsv_()`.

### Сервер не должен «догадываться» при расхождении

После парсинга Apps Script проверяет, что сумма приёмов пищи совпадает с суточным итогом FatSecret.

Текущие допуски:

```text
KCAL_TOLERANCE = 2 kcal
MACRO_TOLERANCE = 0.2 g
```

Если хотя бы одно значение выходит за допуск:

- импорт дня/отчёта отклоняется до записи данных;
- подробная ошибка пишется в `HC_Журнал`;
- Android получает `ok: false` и показывает ошибку пользователю.

**Не увеличивать допуски только для того, чтобы скрыть ошибку импорта.** Большое расхождение почти всегда означает, что появился неизвестный слот/формат FatSecret или изменились колонки экспорта.

### Куда записываются данные

После успешной проверки:

- `Трекер_питания` — данные по приёмам пищи и список продуктов;
- `Питание` — суточные КБЖУ;
- `HC_Журнал` — диагностические сообщения и результат импорта.

`HC_Журнал` — первая точка диагностики любой ошибки FatSecret.

## 6. Диагностика

### A. HealthConnector не появляется в «Поделиться»

Проверить:

1. установлена версия **1.6.3+**;
2. используется именно системная команда FatSecret «Поделиться/отправить отчёт»;
3. `ShareCsvActivity` присутствует в manifest;
4. для `ACTION_SEND` есть `<data android:mimeType="*/*" />`.

Не ограничивать MIME обратно до одного `text/csv`, пока фактический MIME FatSecret не подтверждён на всех используемых устройствах.

### B. HealthConnector появляется, но показывает «Ошибка импорта FatSecret»

Сразу открыть последние строки `HC_Журнал` с `DeviceId = FatSecret` и `Status = ERROR`.

Если сообщение вида:

```text
kcal meals=..., daily=...
```

значит Android/Apps Script распознал не все блоки или неверно распознал их значения.

Порядок действий:

1. получить исходный CSV этого же отчёта;
2. найти проблемную дату;
3. сравнить заголовки всех meal blocks;
4. проверить, нет ли нового названия слота FatSecret;
5. если новый слот является промежуточным — добавить его в `canonicalMealLabel()`;
6. если это новая самостоятельная категория, сначала решить, нужна ли новая категория в таблице или её следует свести к существующей;
7. добавить regression fixture/test;
8. только после этого выпускать новый APK.

### C. `Не найдена секция # Report Details`

Возможные причины:

- передан не пищевой отчёт FatSecret;
- FatSecret изменил формат экспорта;
- Android передал preview/text вместо содержимого файла.

Нужно сохранить фактический payload/CSV и проверить структуру до изменения парсера.

### D. APK не устанавливается поверх текущей версии

Проверить две вещи:

```text
applicationId = ru.doronin.healthconnector.stable
```

и сертификат подписи.

CI проверяет SHA-256 fingerprint стабильного development certificate:

```text
319c0e1944727ba1128e6a8340bd68123b9e8b2cf328b0443e1e4a0387a85a80
```

**Не менять applicationId и не выпускать APK другой подписью**, иначе Android потребует удалить существующее приложение. Удаление может привести к потере локальных настроек/токена.

## 7. Сборка и подпись

Основной workflow:

```text
.github/workflows/android.yml
```

Он запускается на:

- push в `main`;
- pull request;
- `workflow_dispatch`.

Стабильная подпись передаётся через GitHub Actions Secrets:

```text
HC_SIGNING_KEY_B64
HC_SIGNING_STORE_PASSWORD
HC_SIGNING_KEY_ALIAS
HC_SIGNING_KEY_PASSWORD
```

Если secret с ключом подписи отсутствует, workflow выполняет compile/security check, но **не публикует устанавливаемый stable APK**.

При наличии secrets артефакт называется:

```text
health-connector-apk
```

APK внутри сборки:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Не возвращать signing key в git и не хранить его в репозитории.

## 8. Чек-лист релиза

Перед каждой новой устанавливаемой сборкой:

1. Изменить в `app/build.gradle.kts`:
   - `versionCode` +1;
   - `versionName`.
2. Добавить/обновить regression test или fixture для исправляемого сценария.
3. Проверить, что не изменены:
   - `applicationId`;
   - stable certificate;
   - HTTPS-only policy;
   - SecureTokenStore.
4. Push в `main`.
5. Дождаться `Build Android APK`.
6. Убедиться, что шаг `Verify stable APK signature` прошёл.
7. Скачать `health-connector-apk`.
8. Установить APK **поверх** предыдущей версии.
9. В FatSecret экспортировать актуальный пищевой отчёт и отправить через Share Sheet.
10. Проверить:
    - toast `Готово`;
    - последнюю запись FatSecret в `HC_Журнал`;
    - КБЖУ последнего дня в `Питание`;
    - строки приёмов в `Трекер_питания`.
11. После ручной проверки — создать tag/release для этой версии.

## 9. Что желательно сделать дальше

### P0 — regression tests для FatSecret CSV

Сейчас основная защита — серверная проверка целостности и ручной тест. Нужно добавить набор небольших CSV fixtures:

- только основные приёмы пищи;
- `До Завтрака`;
- `После Завтрака`;
- `До Обеда`;
- `До Ужина`;
- `После Ужина`;
- несколько дополнительных слотов в один день;
- дополнительный слот + обычный `Перекус/Другое`;
- `Полдник` должен оставаться отдельным;
- продукты с запятыми/кавычками;
- русский и английский экспорт.

Тест должен доказывать, что после нормализации сумма meal headers равна daily total.

### P0 — сохранить реальный проблемный CSV как обезличенный fixture

Если удастся получить исходный отчёт за 01.09.2026, сделать минимальный обезличенный fixture, воспроизводящий расхождение 2434 → 2568 до исправления.

### P1 — локальная проверка перед отправкой

Android уже понимает структуру блоков. Можно добавить локальную сверку `sum(meals) == daily total` и показывать пользователю точную причину **до** сетевого запроса.

Серверную проверку всё равно оставить как обязательную.

### P1 — сохранять исходный slot

Сейчас все промежуточные слоты сводятся к `Перекус/Другое`, поэтому информация «До завтрака» / «После ужина» теряется как отдельный атрибут.

Если эта аналитика станет нужна, добавить `SourceMealSlot` в модель/таблицу, не ломая каноническую категорию `Перекус/Другое`.

### P1 — автоматические GitHub Releases

После успешного CI и ручной проверки создавать version tag (`v1.6.5`, `v1.6.6`, …) и прикладывать APK к GitHub Release. Тогда не придётся искать «последний правильный artifact» среди Actions runs.

### P2 — SEND_MULTIPLE

Сейчас при `ACTION_SEND_MULTIPLE` используется первый переданный URI. Для FatSecret этого достаточно, но поведение следует либо явно зафиксировать как «один отчёт за импорт», либо реализовать последовательный импорт нескольких файлов.

### P2 — локальная проверка типа отчёта

Wildcard `*/*` нужен для видимости в Android Share Sheet, но из-за него HealthConnector может предлагаться и для посторонних файлов. Можно оставить wildcard в manifest, но перед сетевым запросом локально проверять наличие `# Report Details` и выдавать понятное сообщение «Это не отчёт FatSecret».

## 10. Что НЕ делать при следующем баге

- Не увеличивать `KCAL_TOLERANCE` / `MACRO_TOLERANCE`, если расхождение заметное.
- Не удалять integrity check.
- Не менять `applicationId`.
- Не менять сертификат подписи.
- Не хранить API token или signing key в git.
- Не считать, что у FatSecret всегда только 5 названий meal slots.
- Не исправлять новый слот простым переименованием, если несколько исходных слотов могут свестись в один: их КБЖУ необходимо **суммировать**, а food rows — **объединять**.
- Не сужать Share MIME filters без проверки на реальном FatSecret/Android.
